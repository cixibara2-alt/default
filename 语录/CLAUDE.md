# 语录文件夹规则（仅本目录下会话生效）

## 定位
- 本文件夹负责 Cixibara 语录手册的编辑与版本管理。手册主要在 claude.ai Project / Gemini 里用来解题；这边用 Code 的优势是改文件方便、git 记录版本历史。
- 「Cixibara」——基于数学老师陈晓（昵称"慈禧"）教学风格的 AI 人设手册。手册只放语录，本文件放工作规则；改本文件绝不能动手册里的语录内容。

## 两个版本（重要）
手册维护**两份并行文件**，语录正文完全相同，只有「AI 面向的说明」不同。
- `Cixibara.md` —— **S 版（standard / 人类版）**，是**源头**。**不含**「AI 使用定位」「AI 解题须知」两块，也**删掉词条内的「AI 使用」注解**（如 3-07 那句），内容只有：前言、版权声明、语录正文。给人阅读。**标题带版本号**：`# Cixibara va.b`（主.次两位，不含修订号 .d）。
- `Cixibara-AI.md` —— **AI 版**（原 C/G 两版已合并为这一份），标题 `# Cixibara for AI`，不带版本号。
- `Cixibara-AI.md` 内含 **AI 解题须知 4 条**（含跳过存疑题），第 2、3 条按 AI 能力分两种情形写：**能弹交互选择框的（如 Claude）**弹「工具范围」四选一、高阶解法弹确认框；**不能弹框的（如 Gemini）**默认①基础档、不够用才升最低够用档并注明、高阶解法直接附上。「AI 使用定位」+ 板块 2/3/4 引言叮嘱**克制、避免语气激进**（原 Gemini 版要求，合并后统一适用）。语录词条与 S 版一字不差。

### 本会话（Code）里怎么用
- **在 Code 里解题** → 读 `Cixibara-AI.md`（AI 版）。
- **改语录**（增/删/改词条、改语录正文）→ **两份一起改**，保持语录部分完全一致。
- 只改「AI 说明」（解题须知、使用定位等）→ 只改 `Cixibara-AI.md`。

## 版本历史（只记 git，文件里不写完整历史）
- **完整版本历史只记在 git 提交信息里**，手册文件内不放历史段。回看历史：`git log -- 语录/Cixibara.md`（记录 0709 从新文件重新开始，更早的不算）。
- **提交信息格式（固定）**：`cixibara: v旧→v新 日期 [改动内容]`，日期用 MMDD。**方括号里的改动说明用英文写**（语录原文、词条名等中文内容照抄，不翻译）。例：`cixibara: v5.38.2→v5.39.0 0710 [add entry 2-29 家徒一壁]`。
- 版本号三段式 `va.bc.d`（主.次.修订）：**大改** 次版本 +10 修订归零；**增加语录/新内容** 次版本 +1 修订归零；**bugfix / 纯结构调整** 修订 +1。主版本固定，除非用户要求升级。当前版本号看最近一条 cixibara 提交信息。
- **S 版标题版本号同步规则**：`Cixibara.md` 标题里的 `va.b`（主.次两位）只在**主版本或次版本变化**时更新（大改、增加语录）；**纯 bugfix / 结构调整**（修订号 .d +1）**不改标题**，标题版本号保持不变，直到下次主/次版本变化。

## 工作方式
- 输出简洁、可直接粘贴，改完把新版本内容给用户复制进对应 AI 的 Project。
- 每次改动：改手册文件 → 按上面格式写 git 提交信息 → 合并推送到 `claude/default`。**不动用户文件的结构，不往手册里加历史段。**
- **改语录时**：主动检查是否有"如果被领导看到会有不良影响"的夸张/敏感表述（如影射老师失职、贬低/侮辱学生、拿真实病症开玩笑等），发现了提出来给用户判断，不擅自改写语录内容。

## 配图（GGB 文件，不再截图）
- 需要几何配图时直接生成 **`.ggb` 文件**：手写 `geogebra.xml`（GeoGebra format 5.0，点/线/圆等对象与标签样式全 XML 描述）→ `zip` 打包成 `.ggb`（包内根为 `geogebra.xml`，缩略图可省）→ 交付。不跑无头浏览器截图，不生成 PNG。
- **交付渠道（已验证可用）**：默认聊天里 SendUserFile 直接发（iOS 上点附件 → 分享 → GeoGebra 打开，用户确认这个最方便）；用户要留档时再存一份到 Google Drive 的「GGB配图」文件夹（已建好）。
- GGB 文件按需生成即用，不存进本仓库。
