# 语录文件夹规则（仅本目录下会话生效）

## 定位
- 本文件夹负责 Cixibara 语录手册的编辑与版本管理。手册主要在 claude.ai Project / Gemini 里用来解题；这边用 Code 的优势是改文件方便、git 记录版本历史。
- 「Cixibara」——基于数学老师陈晓（昵称"慈禧"）教学风格的 AI 人设手册。手册只放语录，本文件放工作规则；改本文件绝不能动手册里的语录内容。

## 三个版本（重要）
手册维护**三份并行文件**，语录正文完全相同，只有「AI 面向的说明」不同。**三个文件标题都只写 `# Cixibara`，不写版本号。**
- `cixibara.md` —— **S 版（standard / 人类版）**，是三份的**源头**。**不含**「AI 使用定位」「AI 解题须知」两块，也**删掉词条内的「AI 使用」注解**（如 3-07 那句），只留前言、版权声明、语录正文。给人阅读。**文件里不放「更新记录」段**（历史集中在 `Cixibara.md`，见下）。
- `cixibara-C.md` —— **Claude 版**（由 S 版调整而来）。AI 解题须知 **4 条**、用**交互式**：解题前弹「工具范围」四选一框、有高阶解法弹「是否再解一版」框；语气中性。
- `cixibara-G.md` —— **Gemini 版**（由 S 版调整而来）。AI 解题须知也 **4 条**，但**不弹任何选择框**：默认①基础档、不够用才升最低够用档并注明、有高阶解法直接附上；且「AI 使用定位」+ 板块 2/3/4 引言反复叮嘱**克制、避免语气激进**（Gemini 倾向更冲，需压着来）。
- **两个 AI 版的差别只在「AI 面向说明」**：①使用定位（G 更强调克制）②解题须知（C 弹框 / G 不弹框、默认基础档）③板块 2/3/4 引言语气（G 加克制/不作术语调用）。**两版解题须知都是 4 条**（含跳过存疑题）。语录词条一字不差。以后新的 C/G 差异也只体现在这些说明性文字上。

### 本会话（Code）里怎么用
- **在 Code 里解题** → 读 `cixibara-C.md`（Claude 版）。
- **改语录**（增/删/改词条、改语录正文）→ **三份一起改**，保持语录部分完全一致。
- 只改某一版专属的「AI 说明」（如只调 Gemini 的解题须知）→ 只改那一份。

## 版本历史（集中在独立文档）
- **版本历史只写在 `Cixibara.md`** 这一个文件里；三个手册 md（`cixibara.md`/`-C`/`-G`）内都**不放「更新记录」段、不写版本号**，保持干净。
- 更新历史每行格式：`v旧→v新 日期 [改动内容]`，日期用 MMDD，旧在左新在右，越靠下越新。例：`v5.38.2→v5.39.0 0710 [增加语录]`。
- 版本号三段式 `va.bc.d`（主.次.修订）：**大改** 次版本 +10 修订归零；**增加语录/新内容** 次版本 +1 修订归零；**bugfix / 纯结构调整** 修订 +1。主版本固定，除非用户要求升级。当前版本号看 `Cixibara.md` 最后一行。
- git 提交信息也用同一句 `cixibara: v旧→v新 日期 [改动内容]`（方便命令行回看）。

## 工作方式
- 输出简洁、可直接粘贴，改完把新版本内容给用户复制进对应 AI 的 Project。
- 每次改动：改手册文件 → 在 `Cixibara.md` 追加一行历史 → 提交 → 合并推送到 `claude/default`。
- **改语录时**：主动检查是否有"如果被领导看到会有不良影响"的夸张/敏感表述（如影射老师失职、贬低/侮辱学生、拿真实病症开玩笑等），发现了提出来给用户判断，不擅自改写语录内容。

## 配图（GGB 文件，不再截图）
- 需要几何配图时直接生成 **`.ggb` 文件**：手写 `geogebra.xml`（GeoGebra format 5.0，点/线/圆等对象与标签样式全 XML 描述）→ `zip` 打包成 `.ggb`（包内根为 `geogebra.xml`，缩略图可省）→ 交付。不跑无头浏览器截图，不生成 PNG。
- **交付渠道（已验证可用）**：默认聊天里 SendUserFile 直接发（iOS 上点附件 → 分享 → GeoGebra 打开，用户确认这个最方便）；用户要留档时再存一份到 Google Drive 的「GGB配图」文件夹（已建好）。
- GGB 文件按需生成即用，不存进本仓库。
