# 语录文件夹规则（仅本目录下会话生效）

## 定位
- 本文件夹负责 Cixibara 语录手册的编辑与版本管理。手册主要在 claude.ai Project / Gemini 里用来解题；这边用 Code 的优势是改文件方便、git 记录版本历史。
- 「Cixibara」——基于数学老师陈晓（昵称"慈禧"）教学风格的 AI 人设手册。手册只放语录，本文件放工作规则；改本文件绝不能动手册里的语录内容。

## 三个版本（重要）
手册维护**三份并行文件**，语录正文完全相同，只有「AI 面向的说明」不同：
- `cixibara.md` —— **人类版**，版本号 `va.bc.d`（如 v5.38.0）。**不含**「AI 使用定位」「AI 解题须知」两块，也**删掉词条内的「AI 使用」注解**（如 3-07 那句），只留前言、版权声明、语录正文，给人阅读。
- `cixibara-C.md` —— **Claude 版**，版本号 `va.bc.Cd`（如 v5.38.C0）。AI 解题须知用**交互式**：解题前弹「工具范围」四选一框、有高阶解法弹「是否再解一版」框；语气中性。
- `cixibara-G.md` —— **Gemini 版**，版本号 `va.bc.Gd`（如 v5.38.G0）。**不弹任何选择框**：默认①基础档作答、不够用才升最低够用档并注明、有高阶解法直接附上；且「AI 使用定位」+ 板块 2/3/4 引言反复叮嘱**克制、避免语气激进**（Gemini 倾向更冲，需压着来）。
- **两个 AI 版的唯一差别就在上述「AI 面向说明」**（使用定位、解题须知、板块引言语气）；语录词条一字不差。以后若积累出新的 Claude/Gemini 差异，也只体现在这些说明性文字上。

### 本会话（Code）里怎么用
- **在 Code 里解题** → 读 `cixibara-C.md`（Claude 版）。
- **改语录**（增/删/改词条、改语录正文）→ **三份一起改**，保持语录部分完全一致。
- 只改某一版专属的「AI 说明」（如只调 Gemini 的解题须知）→ 只改那一份，按该版的修订号 +1。

## 版本号规则（三段式：主版本.次版本.修订号，每次改动各自打版本，不再按天封顶）
- 手册文件：`cixibara.md`（新版，说明+语录都在这），文件名固定不带版本号，版本号写在文件内容里。
- **主版本**（第一位）：目前固定不动，除非用户明确要求升级。
- **次版本**：
  - **大改**（整体重构、结构调整、批量改写）→ 次版本 **+10**，修订号归零。例：v5.28.1 → v5.38.0。
  - **增加语录/新内容**（新增词条、补充新内容）→ 次版本 **+1**，修订号归零。例：v5.38.2 → v5.39.0。
- **修订号**：**bugfix**（修正已有内容的错字/措辞/小问题，不涉及新增内容）→ 修订号 **+1**。例：v5.38.0 → v5.38.1。
  - 文件迁移/整合、解决跨会话冲突等**无新增内容、纯结构性调整**的操作，也算 bugfix 一档，应加修订号 **+1**（而不是不变）。
- 每次提交都按当次改动类型单独打版本，**不再有"一天封顶一次"的限制**（旧规则已废弃）。
- 历史版本不另存文件，git 提交历史就是版本记录；回看旧版用 `git log -- 语录/cixibara.md` / `git show`。

## 工作方式
- 输出简洁、可直接粘贴，改完把新版本内容给用户复制进 claude.ai Project。
- 每次改动：更新文件内的版本号 → 提交 → 合并推送到 `claude/default`。
- **提交信息格式（固定）**：`cixibara: v旧→v新 日期 [改动内容]`，日期用 MMDD。例：`cixibara: v5.38.2→v5.39.0 0710 [增加语录]`。
- **改语录时**：主动检查是否有"如果被领导看到会有不良影响"的夸张/敏感表述（如影射老师失职、贬低/侮辱学生、拿真实病症开玩笑等），发现了提出来给用户判断，不擅自改写语录内容。

## 配图（GGB 文件，不再截图）
- 需要几何配图时直接生成 **`.ggb` 文件**：手写 `geogebra.xml`（GeoGebra format 5.0，点/线/圆等对象与标签样式全 XML 描述）→ `zip` 打包成 `.ggb`（包内根为 `geogebra.xml`，缩略图可省）→ 交付。不跑无头浏览器截图，不生成 PNG。
- **交付渠道（已验证可用）**：默认聊天里 SendUserFile 直接发（iOS 上点附件 → 分享 → GeoGebra 打开，用户确认这个最方便）；用户要留档时再存一份到 Google Drive 的「GGB配图」文件夹（已建好）。
- GGB 文件按需生成即用，不存进本仓库。
